Don’t guess whether a regex is dangerous. Attack it.

redoscope reads a regular expression’s automaton, builds the input that forces catastrophic backtracking, runs it against the regex engine in this tab, and times it. You get a verdict, the string that caused it, the timings — and a rewrite that is checked to run fast and still match the same strings.

How a verdict becomes evidence

Matching time is governed by how many distinct paths spell an input, so the question is decided on the automaton, then checked against the real engine.

  1. Parse

    Full ECMAScript syntax, including Annex B forms. Classes, \p{…} and case folding become code-point interval sets.

  2. Compile

    An NFA for what a backtracking engine explores, not the language it accepts: (a|a) is two edges.

  3. Decide ambiguity

    Exponential and polynomial degree, decided on product automata (Weideman et al., CIAA 2016), including the engine’s retry at every offset.

  4. Build a witness

    prefix · pumpⁿ · suffix, with a suffix chosen to make the overall match fail.

  5. Measure

    Run on an escalating ladder in a process or worker that can be killed, then fit the growth curve.

Use it

No runtime dependencies, no build step, no network. Node 22.18 or newer runs the TypeScript source directly.

Command line

node src/cli.ts '^(a+)+$'
node src/cli.ts scan src/ --fail-on polynomial
node src/cli.ts scan . --sarif out.sarif

GitHub Actions

permissions:
  security-events: write
steps:
  - uses: actions/checkout@v4
  - uses: sgoel2be24-cyber/redoscope@v0.2.0
    with:
      path: src
      fail-on: exponential

Library

import { inspect } from "redoscope";

const r = inspect("^(a+)+$");
r.verdict;      // "exponential"
r.exploitable;  // true, measured
r.attack;       // { prefix, pump, suffix }
